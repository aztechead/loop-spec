# PR 100 audit

For the maintainer deciding whether to merge
[aztechead/loop-spec#100](https://github.com/aztechead/loop-spec/pull/100)
(`fix/6.6.4-fastapi-live-run`). After this page you can accept, reject, or
request the listed follow-ups. Line numbers are
[`b981a2a`](https://github.com/aztechead/loop-spec/commit/b981a2a233831766f07cca67aac342f798b12c8e).

**Verdict.** The four FastAPI oneshot defects are really fixed and pinned. The
rest of 6.6.4 is a live-run bundle that only partly matches the claims: one
driver protocol bug undercuts the snapshot-hash change, the new Codex
`agent-type` probe is incomplete and fights the EXECUTE dispatch contract, and
deleting two large “already red” suites unpins behavior this PR still depends
on.

No reviews or CI were on the PR at audit time. Suites run against that commit
(all green): python-path, harness, oneshot-exit-gate, graph-gate.

## What the PR actually fixes

These match the PR body and are tested.

**Hostless remotes.** [`lib/pr-delivery.sh`](https://github.com/aztechead/loop-spec/blob/b981a2a233831766f07cca67aac342f798b12c8e/lib/pr-delivery.sh)
and [`lib/checkpoint-pr.sh`](https://github.com/aztechead/loop-spec/blob/b981a2a233831766f07cca67aac342f798b12c8e/lib/checkpoint-pr.sh)
now read `remote.<name>.pushurl` / `.url` (not `git remote get-url`, which
expands `insteadOf`). A URL with no host in final mode is `pushed-no-pr`;
checkpoint skips `gh`. That is the 6.6.3 bare-path origin bug.

**Lockfiles in the oneshot footprint.**
[`generated_by_manifest`](https://github.com/aztechead/loop-spec/blob/b981a2a233831766f07cca67aac342f798b12c8e/lib/oneshot-exit-gate.sh#L78-L98)
treats `uv.lock`, `.python-version`, npm/Cargo/Go/Gem/Composer lockfiles, and
`.gitignore` next to a named manifest as inside the footprint. An orphan
lockfile still escalates.

**Post-gate drift (single-repo).** `phase_end` records `headSha`. DELIVER
refuses `post_gate_drift` when non-artifact files moved after the last
`next == "deliver"` event, and `no_gate_record` when `headSha` exists but
nothing routed to deliver. Artifact-only commits are excluded.

**Reviewer cite.** [`agents/code-reviewer.md`](https://github.com/aztechead/loop-spec/blob/b981a2a233831766f07cca67aac342f798b12c8e/agents/code-reviewer.md)
now points at `{probe_dir}/../skills/shared/approach-selection.md`, which is the
plugin `lib/` brief input the oneshot/VERIFY dispatch already supplies.

**Other items that look right:** pyenv shim bypass via a private directory that
contains only `python3` (the Homebrew-`claude` shadow is a real regression to
have caught); `phase-exit.sh --check`; gate always rerun on `next`;
pending-dispatch marker; `grep_symbol` / `grep -qw`; critique ceiling scaling
(the 40-findings case passed); `task add-files`; `LOOP_SPEC_SAME_SESSION`;
documented `LOOP_SPEC_DISPATCH_WAIT_MINS`.

## High: the code does not do what the PR says

### 1. `NOTE [snapshot]` is printed on stdout, so the lead can miss `NEXT`

The changelog says the source-hash mismatch is “a `NOTE [snapshot]` plus a
warning, not an escalation” so a development clone that moves mid-phase (the
Codex EXECUTE run) can continue.

[`lib/graph/driver.py` L1273–L1276](https://github.com/aztechead/loop-spec/blob/b981a2a233831766f07cca67aac342f798b12c8e/lib/graph/driver.py#L1273-L1276)
prints that note on stdout. [`skills/cycle/SKILL.md` L90–L93](https://github.com/aztechead/loop-spec/blob/b981a2a233831766f07cca67aac342f798b12c8e/skills/cycle/SKILL.md#L90-L93)
parses **the first line** of `cycle-driver.sh next`. Those rules are `NEXT` /
`REDO` / `HANDOFF` / `PAUSED` / `DONE` / `ABORT`. There is no `NOTE` rule. On
the exact path this change exists for, the first line is `NOTE [snapshot]...`
and `NEXT` is later in the same stdout. The driver continues; the lead
following the skill may not.

This PR already put the critique-ceiling note on **stderr** so JSON callers keep
parsing ([`lib/critique-step.sh` L144](https://github.com/aztechead/loop-spec/blob/b981a2a233831766f07cca67aac342f798b12c8e/lib/critique-step.sh#L144)).
The snapshot note should do the same. Pre-existing sibling:
[`NOTE [escalate]` is also printed to stdout](https://github.com/aztechead/loop-spec/blob/b981a2a233831766f07cca67aac342f798b12c8e/lib/graph/driver.py#L1361).

### 2. Codex `agent-type` fights the EXECUTE dispatch contract

[`skills/shared/execute-subagent.md` L270–L276](https://github.com/aztechead/loop-spec/blob/b981a2a233831766f07cca67aac342f798b12c8e/skills/shared/execute-subagent.md#L270-L276)
now says: probe `harness.sh agent-type`, and pass `subagent_type` only when the
answer is not `default` — “that only happens under Codex” with
`~/.codex/agents/loop-spec-<role>.toml`.

Two pages later the implementer stanza is still ([L306–L307](https://github.com/aztechead/loop-spec/blob/b981a2a233831766f07cca67aac342f798b12c8e/skills/shared/execute-subagent.md#L306-L307)):
this dispatch uses the DEFAULT agent (not loop-spec:implementer), so the agent
definition’s directives do not apply.

On Codex that stanza is false if the TOML exists. `codex-install.sh` copies
`agents/implementer.md` into `developer_instructions`. Passing
`agent_type: "loop-spec-implementer"` applies that charter **and** the
self-contained EXECUTE prompt that says the charter does not apply. Claude Code
omitted `subagent_type` here on purpose (self-contained prompt, no nested
worktree isolation). This change reintroduces the role charter on one harness
only.

The probe is also the wrong install path. `--project` writes `$PROJECT/.codex/agents/`
([`lib/codex-install.sh` L80–L95](https://github.com/aztechead/loop-spec/blob/b981a2a233831766f07cca67aac342f798b12c8e/lib/codex-install.sh#L80-L95)).
[`harness.sh agent-type`](https://github.com/aztechead/loop-spec/blob/b981a2a233831766f07cca67aac342f798b12c8e/lib/harness.sh#L211-L224)
only looks at `${CODEX_HOME:-$HOME/.codex}/agents/loop-spec-$role.toml`. A
project install that this installer documents will always answer `default`.
Fail-safe (omit the type, use the self-contained prompt) is the better EXECUTE
behavior anyway, which makes the new probe mostly a no-op for `--project` and a
contradiction for a user install.

### 3. Deleting the two red suites unpins 6.6.3 and this PR’s own `next` changes

`tests/lib/cycle-driver.test.sh` (282 cases) and
`tests/lib/execute-prepare.test.sh` are deleted because pause/intent and a
`/private/var` symlink case were red on `main`. Replacement is the new
cycle-start-resume suite (three start/resume cases) plus one
`artifactsCommitted` check in `tests/lib/execute-step.test.sh`.

Dropped coverage includes `next` handoff, same-session edges, REDO/escalate,
oneshot review, worktree `next`, and the 6.6.3 reverse-`blockedBy` / workspace
packet tests. This PR **changes** `cmd_next` (always run the gate, snapshot
NOTE, `LOOP_SPEC_SAME_SESSION`) and `lib/execute-prepare.sh` (auto-commit) with
almost none of that still pinned. A red suite that nobody fixes gates nothing;
deleting it also gates nothing, including the new behavior.

`tests/oneshot-artifact-budget.test.sh` was an offline fixture copier, not a
live eval. Removing it is policy overreach.

## Harness API integration

The plugin’s four peers are Claude Code, OpenCode, ADK, and Codex. The new
`agent-type` verb is Codex-only and the EXECUTE skill now says so in a way that
fights the other three contracts.

| Harness | Subagent API | What this PR does | Problem |
|---|---|---|---|
| Claude Code | `Agent({subagent_type?})`; omit = default | `agent-type` → `default`; omit type | Correct for this rung |
| OpenCode | `task` **requires** `subagent_type`; hyphen ids | Still `default`; new prose says only Codex passes a type | [`opencode-harness.md`](https://github.com/aztechead/loop-spec/blob/b981a2a233831766f07cca67aac342f798b12c8e/skills/shared/opencode-harness.md#L72) already maps omitted EXECUTE dispatches to `loop-spec-implementer` / `loop-spec-spec-compliance-reviewer`. The new “only happens under Codex” line in the dispatch procedure is easy to follow instead of that mapping. OpenCode agents live under `.opencode/agents/` or the config dir; `agent-type` never looks there |
| ADK | `dispatch_subagent({subagent_type, ...})`; unknown type is a structured error | Same `default` / omit | ADK has **no** “when omitted, pick the role” clause. Omitting the field is a failed dispatch, not a default agent ([`adk-harness.md` L145–L146](https://github.com/aztechead/loop-spec/blob/b981a2a233831766f07cca67aac342f798b12c8e/skills/shared/adk-harness.md#L145-L146)) |
| Codex | `spawn_agent` `agent_type: loop-spec-<role>` from TOML | Looks only at `CODEX_HOME` / `~/.codex` | Misses `--project` `.codex/agents/`; when it hits, it applies the role charter this rung was written to avoid |

`harness.sh subagents` still answers `true` for all four, so the subagent
EXECUTE ladder is live everywhere. The new probe does not make that ladder’s
type field correct except on a user-level Codex install.

Other harness notes that are fine: `LOOP_SPEC_SAME_SESSION` is implemented in
`record_transition` (all harnesses) and only *also* in the Claude
`phase-handoff-guard`. `cycle-stamp-guard` / `.pending-dispatch` is a Claude
Stop hook; Codex/OpenCode/ADK do not have that deny, so they do not need the
marker. `agents/code-reviewer.md` `{probe_dir}` is the existing brief contract,
not a harness template substitution.

## Sibling bugs of the live-run fixes

**`uv init` still has a fourth-file sibling.** Live run 2 escalated on
`.gitignore`; that is now owned by any of several manifests. `uv init` also
writes `README.md` and often `main.py` / `hello.py`. Those are still outside the
footprint unless named. The skill only tells the lead to commit lockfile +
`.python-version`. Same class of bug, next file.

**Lockfile map is uv-centric.** No `Pipfile.lock`, `requirements.lock`,
`.nvmrc` / `.node-version` next to `package.json` (the analogue of
`.python-version`). Fine for this FastAPI run; not the general rule the
changelog states.

**`post_gate_drift` / `no_gate_record` are single-repo only.** The whole block
sits under `if [[ -z "$workspace_root" ]]`
([`lib/deliver.sh` L140](https://github.com/aztechead/loop-spec/blob/b981a2a233831766f07cca67aac342f798b12c8e/lib/deliver.sh#L140)).
Workspace DELIVER can still ship an ungated commit. `headSha` is
`git -C "$feature_dir"`; in workspace mode the feature dir is at the workspace
root (often not a git repo), so `headSha` is null and the skip is consistent —
protection is just missing.

**`execute-prepare.sh` auto-commit does not fail loudly.** The script is
`set -uo pipefail` without `-e`
([L63–L73](https://github.com/aztechead/loop-spec/blob/b981a2a233831766f07cca67aac342f798b12c8e/lib/execute-prepare.sh#L63-L73)).
If `commit` fails (no `user.email`, hook), stdout is discarded,
`artifactsCommitted` is still the **previous** HEAD, and the dirty SPEC that
blocked `integrate-task` is still dirty. Workspace mode is skipped entirely
(the motivating Codex run was single-repo).

**`add-files` does not widen the already-rendered brief / worktree allow-list.**
It updates sidecar, `tasks-collapsed.json`, and `prepare.json`. That is enough
if the lead re-dispatches as the skill says. A rework in the same worktree
without a new dispatch still has the old `task.files`.

**Hostless checkpoint error code is still `gh_missing`.** Supervisors cannot
tell “install `gh`” from “this remote is a path.” Outcome `pushed-no-pr` is the
right final-mode behavior.

**`oneshot-spec-lint` `route: full` is stricter than the probe.** The probe
strips quotes (`route: "full"`). The lint stand-down is `^route:\s*full\s*$` on
the raw line. The gate writes unquoted `route: full`, so the live path is fine;
a quoted YAML value would still get oneshot-shape REDOs on a full route.

## Quality

- **CHANGELOG 6.6.4 “Changed”** glues the `.gitignore` bullet onto the
  python-path PATH-prefix paragraph. Two changes, one sentence.
- **python-path.sh** only recognizes pyenv shims
  (`*/.pyenv/shims/python3|*/pyenv/shims/python3`). asdf/mise users still pay
  the tax. The sticky dir `${TMPDIR:-/tmp}/loop-spec-python-$(id -u)` is a
  predictable path in `/tmp` (classic symlink plant). The second-cut “link only
  `python3`” design is right.
- **python-path test header** still says the probe “resolves to the
  interpreter's directory” (the cut that shadowed `claude`).
- **`phase-exit --check`** still runs gates and `oracle_gate`; it only skips
  artifact pointers, commit, and `close_phase`. Oracle is read-only here, so
  this is mostly fine.
- **`.pending-dispatch` only helps if `dispatch` is emitted at launch.**
  `execute-step` does that. Oneshot’s in-harness reviewer emits the event in the
  same bash call that **reads the result**, i.e. after the agent returns — so
  the Stop-during-review window for oneshot is still unmarked.

## Suggested merge bar

Do not merge on the snapshot NOTE or the EXECUTE/`agent-type` contradiction
without a fix. The original four FastAPI fixes can stand.

Minimum follow-ups:

1. Print `NOTE [snapshot]` (and the existing `NOTE [escalate]`) on stderr, or
   skip NOTE lines in `skills/cycle/SKILL.md` before the first protocol line.
2. Either keep EXECUTE on the default agent on every harness (including Codex),
   or change the implementer stanza and add OpenCode/ADK registry probes that
   match `codex-install` / `opencode-install` / ADK role ids — including project
   `.codex/`.
3. Restore the driver and prepare suites (fix the red cases) instead of
   deleting them; this PR’s `next` and `execute-prepare` changes need those
   pins.
4. Decide whether `README.md` / default `main.py` from `uv init` are also
   manifest output, and whether workspace DELIVER gets `post_gate_drift`.
