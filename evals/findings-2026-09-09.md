## Findings

### 1. A whole-description title makes a branch git cannot lock

The prompt was 470 characters. `cycle-driver.sh start` slugified all of it into the
branch name, `git worktree add` failed with `fatal: cannot lock ref`, and the lead
read `lib/git-ops.sh`, `lib/parse-invocation.sh`, and `lib/cycle-driver.sh`, probed
`begin --help`, then wrote `intake-spec.md`, committed it to the fixture's `main`, and
re-issued `begin` with the file. Twenty-five tool calls and a commit the ask never
requested. Fixed: `lib/git-ops.sh slugify` bounds a slug at 64 characters on a word
boundary; the title keeps the full text. Offline: `bash tests/lib/git-ops.test.sh`
(C2, C3).

### 2. `begin --help` initializes a feature named "help"

The parser treated the flag as a description; autonomous mode carried it to
`feat/help` and a worktree the lead removed by hand. Fixed: `lib/parse-invocation.sh`
refuses any flag but `--no-run` with the token list on stderr. Offline:
`bash tests/lib/parse-invocation.test.sh` (the `--help` cases).

### 3. A local catalog stood in for a runtime's release list

The container had no 3.14. The lead asked the tools the version directive names:
`uv python list` answered that 3.14.0rc2 was the newest 3.14, the lead installed it,
pydantic 2.13 crashed on the release candidate's `typing` module, and the next twenty
commands read pydantic's source, tried apt, tried two pydantic pins, hit the GitHub
rate limit on `uv self update`, installed uv 0.12.11 from PyPI, and got 3.14.7. Zero
WebSearch or WebFetch calls in the run, though the driver allows both. The directive's
ordering (manifest, package manager, then web) is right for a library, whose package
manager answers from the registry, and wrong for a runtime, whose "package manager"
step is a cached list. Fixed: the version row of
`skills/shared/engineering-directives.md` sends a runtime version to the release page
or a network registry and requires one web source for any "latest" or "not available"
claim. Pinned by `tests/engineering-directives-coverage.test.sh`.

### 4. Every Agent call returned the async stub

All eight dispatches carried `run_in_background: false` and all eight tool results
were the launch stub; the reports arrived as notifications, and each cost the lead a
turn of `ReadNotifications` or a scheduled wake-up. The 6.3.0 contract's other half
held: no re-dispatch. Claude Code's fork mode backgrounds subagents regardless of the
key; the documented foreground switch is `CLAUDE_CODE_DISABLE_BACKGROUND_TASKS=1`.
Fixed: `evals/eval_run.py` sets it in the child environment,
`skills/shared/dispatch.md` and `skills/shared/claude-harness.md` name it, and the
supervisor quick start tells an SDK embedding to set it. Not yet measured: the turn
count with it set.

### 5. A FLAG-only planner round before the critique

PLAN dispatched the planner three times: author, fix the mechanical FLAGs, apply the
critique fix-list. The skill says the challenger's findings pass goes out in the same
response as the gate command and the FLAG lines join its fix-list; the lead fixed the
FLAGs first. Fixed in prose only: `skills/plan/SKILL.md` now says a FLAG-only round is
the loop the section removed. A probe cannot see a dispatch order, so this one stays a
judgment the eval keeps measuring.

### 6. `task_start` and `task_end` emitted twice per task

`lib/execute-step.sh dispatch` and `integrate` emit both since the 6.2.0 fold, and
`skills/shared/execute-subagent.md` still told the lead to emit them by hand. Every
task logged four events instead of two. Fixed: the contract says the steps emit them
and never by hand; `tests/console-observability-coverage.test.sh` pins the step.

### 7. A dirty feature worktree was called `rebase-conflict`

The lead had edited SPEC.md and feature.json in the feature worktree after task-001
was dispatched and left them uncommitted; `task integrate` refused through
`lib/integrate-task.sh check-dirty-worktree` and `lib/execute-step.sh` mapped every
unlisted reason to `rebase-conflict`. The lead ran `git status`, `git diff`, committed,
and retried; one lost round. Fixed: the step maps the dirty-worktree reasons to
`dirty-worktree` and passes the script's detail, which now lists the paths.
